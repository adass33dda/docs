## The basics

<AccordionGroup>
  <Accordion title="Sanity isn't responding to my commands">
    Check these in order:

    1. Sanity's role is above the roles it needs to manage. Drag it up in **Server Settings \> Roles**.
    2. Sanity can see the channel you're typing in. Check channel permissions.
    3. You're using the correct prefix. Default is `,` (comma). Confirm with `,prefix`.
    4. Sanity is actually online. Check the member list or run `,ping`.

    Still nothing? The bot might be under maintenance. Check the [support server](https://discord.gg/ajJM66bxQZ) announcements.
  </Accordion>

  <Accordion title="I'm getting 'missing permissions' errors">
    Two things to check:

    - **Discord permission**: Sanity needs the real Discord permission to perform the action. Ban commands need Sanity's role to have `Ban Members`, and Sanity's role has to be above the target's role.
    - **User permission**: You need permission to run the command. If you're not the owner, you need either the real Discord permission or a matching [fake permission](/security/fakepermissions).

    Run `,help (command)` to see exactly which permission the command needs.
  </Accordion>

  <Accordion title="How do I change the prefix?">
    ```txt
    ,prefix set !
    ```

    Replace `!` with any character. You can still use `@Sanity` as a mention prefix at any time.
  </Accordion>
</AccordionGroup>

## Security features

<AccordionGroup>
  <Accordion title="Antinuke punished the wrong person">
    Antinuke only fires against accounts that aren't on your admin whitelist. If someone legitimate got punished, whitelist them:

    ```txt
    ,antinuke admin @user
    ```

    Then unpunish them manually (unban, restore roles). Sanity doesn't auto-reverse punishments because you should confirm the account isn't actually compromised first.
  </Accordion>

  <Accordion title="A trusted admin's account got hacked and nuked the server">
    Sanity's antinuke should have caught this if the admin wasn't whitelisted. If they were whitelisted, the attacker used their trust, which is exactly what fake permissions prevent.

    Recovery:

    1. Remove the compromised admin from the whitelist: `,antinuke admin remove @user`.
    2. Ban them: `,ban @user compromised`.
    3. Check `#case-log` for the full action list.
    4. Use `,restore` if the channel/role structure needs rebuilding (server-owner-only).

    Going forward: no one gets real admin. Everyone moderates through fake permissions.
  </Accordion>

  <Accordion title="My server is getting raided right now">
    Turn on lockdown mode immediately:

    ```txt
    ,lockdown
    ```

    This freezes new joins and posts in public channels. Then check `,antiraid` settings and tune the threshold down while you handle the wave.

    After the raid ends, run `,unlockdown` to reopen the server.
  </Accordion>

  <Accordion title="Fake permissions aren't working for my staff">
    Two common causes:

    - The permission name is wrong. Run `,help (command)` to find the exact permission string.
    - Sanity's role sits below the role of the person being actioned. Drag Sanity's role up.

    View what a role currently has:

    ```txt
    ,fakepermissions list @role
    ```
  </Accordion>
</AccordionGroup>

## Setup and customization

<AccordionGroup>
  <Accordion title="I deleted the jail or mute role by accident">
    Rebuild the mute roles without touching anything else:

    ```txt
    ,setupmute
    ```

    For the full moderation setup (jail role, jail channel, case log), run `,setup` again.
  </Accordion>

  <Accordion title="Can I use my own avatar and banner for Sanity in my server?">
    Yes. See the [Customization page](/customization). Only the server owner can run these commands.
  </Accordion>

  <Accordion title="Can I hide the bot from certain channels?">
    Yes, use Discord's built-in channel permissions. Deny **View Channel** for `@Sanity` in any channel it shouldn't touch. Security features still function; commands just won't work inside those channels.
  </Accordion>
</AccordionGroup>
