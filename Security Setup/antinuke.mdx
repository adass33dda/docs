## Overview

### Why use an antinuke system?

An antinuke system stops trusted staff from abusing their permissions, whether the account is compromised or the person just went rogue. It is the safety net that keeps a single bad actor from tearing your server apart.

### How does the antinuke work?

Sanity tracks how many destructive actions a moderator performs inside a short window. If that count crosses your threshold, the moderator is punished immediately and the owner is notified.

## Configuring the antinuke

<Tip>
  Discord recently rolled out a **mass ban** feature that can remove **100\+ members** in seconds. It is **HIGHLY** recommended to use fake permissions to keep this feature away from moderators.
</Tip>

### Allowing users to configure the antinuke

By default, only the **server owner** can configure the antinuke. You can grant that access to another user with the `antinuke admin` command.

<Warning>
  This is a dangerous command and gives the user full control over the antinuke configuration.
</Warning>

<CodeGroup>

```txt Syntax
,antinuke admin (user)
```

```txt Example
,antinuke admin @Inboards
```

</CodeGroup>

### Exempting users from the antinuke

Use `antinuke whitelist` to let a user bypass the antinuke entirely. This is also how you approve bots when `botadd` protection is enabled.

<Warning>
  This is a dangerous command and lets the user bypass antinuke completely.
</Warning>

<CodeGroup>

```txt Syntax
,antinuke whitelist (user)
```

```txt Example
,antinuke whitelist @Inboards
```

</CodeGroup>

## Enabling an antinuke module

Every module accepts the same flags to control how strict it is and what happens when the limit is hit.

### Available Flags

<AccordionGroup>
  <Accordion title="Threshold">
    The threshold is the number of actions a moderator can perform before being punished.

    <Info>
      Keep the threshold between `1` and `6` to stay safe.
    </Info>

    <CodeGroup>

    ```txt Syntax
    --threshold (number)
    ```

    ```txt Example
    --threshold 3
    ```

    </CodeGroup>
  </Accordion>

  <Accordion title="Punishment">
    The punishment applied to the moderator when the threshold is exceeded.

    <Info>
      Available punishments are listed in the [punishments](#punishments) section.
    </Info>

    <CodeGroup>

    ```txt Syntax
    --do (punishment)
    ```

    ```txt Example
    --do ban
    ```

    </CodeGroup>
  </Accordion>

  <Accordion title="Command Detection">
    Whether Sanity commands (like `,ban`) should count toward the threshold.

    <CodeGroup>

    ```txt Syntax
    --command (on | off)
    ```

    ```txt Example
    --command on
    ```

    </CodeGroup>
  </Accordion>
</AccordionGroup>

### Punishments

Choose how Sanity responds when someone trips a module threshold. Pass any of these values to `--do` when configuring a module.

<CardGroup cols={3}>
  <Card title="Strip" icon="scissors">
    Removes dangerous permissions from the offender's roles.
  </Card>

  <Card title="Kick" icon="door-open">
    Removes the offender from the server.
  </Card>

  <Card title="Ban" icon="hammer">
    Permanently bans the offender from the server.
  </Card>
</CardGroup>

## Disabling an antinuke module

Disable a module with the same command you used to enable it, just swap `on` for `off`.

<CodeGroup>

```txt Syntax
,antinuke (module) off
```

```txt Example
,antinuke ban off
```

</CodeGroup>

### Setting the antinuke log channel

Route every antinuke event, threshold trip, punishment, and whitelist change, to a dedicated channel so your staff can review the audit trail in real time.

<CodeGroup>

```txt Syntax
,antinuke setlog (channel)
```

```txt Example
,antinuke setlog #antinuke-logs
```

</CodeGroup>

<Tip>
  Pick a channel that only your admin and moderator roles can read. Antinuke logs contain member IDs and moderator actions you do not want public.
</Tip>

  ![Setting the antinuke log channel](/images/setlog.png)
