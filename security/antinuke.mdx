## Overview

### Why run antinuke?

Even trusted staff can go rogue, get compromised, or make a costly mistake. Antinuke acts as a safety net: it watches sensitive actions across the server and steps in the moment something looks like sabotage.

### How Sanity's antinuke works

Each module tracks a specific type of destructive action (bans, kicks, role deletes, and so on). When a member crosses the threshold you set within a short window, Sanity automatically applies the punishment you chose and notifies the owner so nothing slips by unnoticed.

## Configuring antinuke

<Tip>
  Discord's built-in **mass ban** tool can remove **100\+** members in a single click. Pair antinuke with [fake permissions](/security/fake-permissions) so staff never touch that button in the first place.
</Tip>

### Granting configuration access

By default only the **server owner** can change antinuke settings. To let a trusted person help manage it, promote them with `antinuke admin`.

<Warning>
  Antinuke admins can rewrite the entire configuration. Only give this to people you'd trust with the server itself.
</Warning>

<CodeGroup>

```txt Syntax
,antinuke admin (user)
```

```txt Example
,antinuke admin @Dom
```

</CodeGroup>

<Frame>
  ![Antinuke admin toggle](/images/antinuke/admin.png)
</Frame>

### Whitelisting a user

Some members (bot developers, other security bots, alt accounts) need to perform actions that would normally trip antinuke. Add them to the whitelist so they're skipped.

<Warning>
  Whitelisted users bypass antinuke completely. Keep this list short.
</Warning>

<CodeGroup>

```txt Syntax
,antinuke whitelist (user)
```

```txt Example
,antinuke whitelist @Dom
```

</CodeGroup>

<Frame>
  ![Antinuke whitelist toggle](/images/antinuke/whitelist.png)
</Frame>

## Enabling a module

### Available flags

These flags shape how each module behaves.

<AccordionGroup>
  <Accordion title="Threshold">
    How many matching actions a member can take before Sanity punishes them.

    <Info>
      Anything between `1` and `6` is a solid starting range for most servers.
    </Info>

    <CodeGroup>

    ```txt Syntax
    --threshold (number)
    ```

    ```txt Example
    --threshold 3
    ```

    </CodeGroup>
  </Accordion>

  <Accordion title="Punishment">
    What Sanity does to the offender once they trip the threshold.

    <Info>
      See [punishments](/security/punishments) for the full list of options.
    </Info>

    <CodeGroup>

    ```txt Syntax
    --do (punishment)
    ```

    ```txt Example
    --do ban
    ```

    </CodeGroup>
  </Accordion>

  <Accordion title="Command detection">
    Also count Sanity commands (like `,ban` or `,kick`) toward the threshold, not just raw Discord actions.

    <CodeGroup>

    ```txt Syntax
    --command (on | off)
    ```

    ```txt Example
    --command on
    ```

    </CodeGroup>
  </Accordion>
</AccordionGroup>

### Available modules

<AccordionGroup>
  <Accordion title="Protect the vanity URL">
    Stops members from claiming or wiping the server's custom invite.

    <Warning>
      Discord doesn't let bots restore a vanity once it's changed, so prevention is the whole game here.
    </Warning>

    <CodeGroup>

    ```txt Syntax
    ,antinuke vanity (on | off) --do (punishment)
    ```

    ```txt Example
    ,antinuke vanity on --do ban
    ```

    </CodeGroup>

    <Frame>
      ![Vanity antinuke module](/images/antinuke/vanity.png)
    </Frame>
  </Accordion>

  <Accordion title="Block unauthorized bots">
    Prevents anyone from adding new bots to the server without approval.

    <Info>
      To bring in a bot you actually want, whitelist its ID first with `,antinuke whitelist (bot ID)`.
    </Info>

    <CodeGroup>

    ```txt Syntax
    ,antinuke botadd (on | off)
    ```

    ```txt Example
    ,antinuke botadd on
    ```

    </CodeGroup>

    <Frame>
      ![Botadd antinuke module](/images/antinuke/botadd.png)
    </Frame>
  </Accordion>

  <Accordion title="Guard against mass bans">
    Catches staff or attackers trying to sweep the member list with bans.

    <Info>
      Turn on `--command on` so `,ban` spam counts too.
    </Info>

    <CodeGroup>

    ```txt Syntax
    ,antinuke ban (on | off) --threshold (number) --do (punishment) --command (on | off)
    ```

    ```txt Example
    ,antinuke ban on --threshold 3 --do ban --command on
    ```

## Disabling a module

Run the same command you used to enable it, but pass `off` instead of `on`. Any thresholds you configured are remembered if you turn it back on later.
